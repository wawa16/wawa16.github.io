WORK PROJECT / CYBERSECURITY

Certificate-based SSH access for robot fleets

Centralized SSH certificate issuance with private AWS connectivity and robot-side credential verification.

  • SSH certificates
  • AWS EC2
  • VPC
  • Network security

Project context

Designed and implemented a centralized SSH Certificate Authority (CA) on an Amazon EC2 instance within an AWS VPC to secure remote access to a fleet of robots. The CA authenticated users before issuing SSH certificates. Robots validated the presented certificates against the trusted CA and verified that clients possessed the corresponding private keys during the SSH handshake. Integrated a Network Load Balancer (NLB) with a VPC endpoint and configured security groups to provide additional network protection.

My contributions

  • Centralized access control: Authenticated users through a central certificate issuance service, reducing reliance on individually distributing and maintaining user public keys across robots.
  • Trusted, verifiable credentials: Used CA-signed SSH certificates so robots could verify that access credentials came from an authorized issuer.
  • Proof of private-key possession: Required clients to demonstrate possession of the private key associated with their certificate, preventing a copied certificate alone from granting access.
  • Protected certificate issuance: Secured communication between clients and the CA to protect authentication and certificate requests.
  • Private network access: Used an NLB-backed VPC endpoint to provide private connectivity to the CA service within the AWS network.
  • Defense in depth: Combined VPC isolation, endpoint connectivity, security group restrictions, user authentication, and robot-side cryptographic verification to enforce security at multiple layers.
  • Restricted network reachability: Configured security groups to limit permitted traffic to required sources, ports, and services, reducing the exposed attack surface.
